PLAN | `docs/PLAN-DEEPZOOM.md` — the mechanism, slices D1–D4, and the acceptance criterion. `WEBGL_ZOOM_CAP = 10000` (`app.js:424`) is an HONEST float32 ceiling (≈1.7e4 by the arithmetic in the plan), not a timid setting, so raising it is not available: the FORMULATION must change, and GLSL ES has no `double` in any version.
AMPLIFIER | colour is a STAIRCASE in the escape value in BOTH renderers and nothing smooths it — CPU builds a `Uint32Array` LUT with one entry per INTEGER iteration (`fractalViewer.js:197-208`), GPU uses `float t = float(iter)/float(u_maxIter)`. So any precision change can flip a pixel a whole band, and colour cycling moves the bands: that is the pop the owner remembers. A continuous colour function makes a hop INVISIBLE rather than merely small.
FORK-TAKEN | smooth colour REPLACES the banded look. Rejected: keeping the integer staircase — it cannot satisfy the owner's own requirement, since any hop can flip a band. If the banded look is wanted back it becomes a colour-mode toggle, not the default.
EVIDENCE-PENDING | probe `b9243a50-ad14-4a4a-badb-474367419c36` is measuring under `/tmp/fv-gpu-probe`: where float32 actually breaks, whether double-float compensation fixes it and its relative cost, and precisely what perturbation requires.
